旗舰项目 · ParanoidBSD

在这个操作系统里，权限靠 持有，而不是默认拥有

ParanoidBSD 把 HardenedBSD 15-STABLE 移植到 C++23 模块，并在 HBSD 本身已有的加固之上加了一层能力与句柄核心。桌面是 KDE Plasma 6。BSD 代码树就是行为规格 — 而且是照原样移植的，连 bug 一起。

问题所在

环境权限是你打不了补丁的那个 bug

在传统的 Unix 上，一个进程并不 持有 打开 /etc/master.passwd的权利。它只是提出请求，内核事后才根据这个进程自称是谁来做决定。系统上的每一个资源，每个进程都叫得出名字。名字空间是全局的、环境性的；检查是事后才补上的。

这就是为什么字体渲染器里一个解析 bug 能变成一次凭据窃取。渲染器从来就不需要口令文件 — 但架构里没有任何东西拦着它去要。

HardenedBSD 在这件事上已经做了不少正经工作：ASLR、源自 PaX 的缓解措施、SafeStack、CFI、加固过的内存分配器。PBSD 把这些全部保留，并改变底下那个问题的形状 — 从 “这个进程被允许吗？” 到 “这个进程持有指向它的句柄吗？”

回答同一次系统调用的两种方式

// Ambient authority — the traditional path
int fd = open("/etc/master.passwd", O_RDONLY);
// kernel walks a global namespace, then
// checks uid/gid/MAC after the fact

// Handle nucleus — the PBSD path
auto f = dir_handle.open("master.passwd", Rights::Read);
// there is no global namespace to walk.
// no handle, no name, no operation.

这是差异的示意形状，不是逐字的 API 清单。权威的模型在 docs/.

移植

四个阶段，以及一个从不给自己背书的模型

把一个 BSD 的用户态和内核手工移植到 C++23 是十年的工作量。让语言模型重写文件来移植，则是一条快速产出看着像样的垃圾的路。PBSD 两条都不走。

第 1 阶段

清单

tools/inventory_c_sources.py 与 clang_cxx23_port.py 按难度给每个 C 文件打分，并写出 c_inventory.csv。范围上没有任何东西是靠猜的。

第 2 阶段

确定性流程

run_todo_passes.py 按第 0–4 级施加安全的机械式重写。不涉及任何模型。流程拒绝处理的东西都会记进 refusals.jsonl ，而不是硬推过去。

第 3 阶段

智能体循环

pbsd.py 用 DeepSeek Flash 填补打了桩的和被拒绝的文件，必要时以最大推理力度升级到 Pro — 默认 48 个 Flash 工作进程和 24 个 Pro 工作进程。 这就是这次 Kickstarter 众筹要资助的部分。

第 4 阶段

验证关卡

编译、ASan、UBSan、差分执行和 IR 比对。一个只是能编译的文件就是 未验证。失败的记录落在 agent_port_failures.jsonl.

“等于”必须意味着什么

一次移植就是一个等价性的主张

说一个文件移植好了，就是在说新的那个行为和旧的一样。这是一个主张，而主张需要证据。一份能编译的 C++23 重写只是一个看着像样的线框；它还不是同一个小恶魔。

所以那个等号就是关卡。差分执行把两边都跑一遍，比较可观察到的行为。IR 比对检查它们对编译器来说是不是同一个意思。在其中一项通过之前，这个文件在迁移日志里一直敞着，也不计入进度 — 不管它看起来多完整。

让这件事站得住脚的规矩是： 模型不为自己背书。它提议，确定性工具裁决。仓库里每一条不可谈判的规矩都是为了保住这条边界 — 这也是为什么光靠在推理上多花钱，并不能把这次移植跑得更快。
不可谈判的规矩

这个仓库真正遵守的规矩

在差分验证或 IR 验证通过之前，没有哪个文件算做完
能编译一律当作未验证。一个移植好的文件，要么在差分执行下产生与 HardenedBSD 原件完全相同的可观察行为，要么在 IR 层面对得上。两样都没过的文件在迁移日志里一直敞着，也不计入进度数字。
照原样移植 — 不要悄悄“修好”原件里的 bug
HardenedBSD 代码树就是行为规格。如果原件有缺陷，移植就把这个缺陷一起复现出来，因为差分测试分不清一次修复和一次回归。改进放到之后再做，单独记录，这样改动是看得见、可复查的，而不是埋在一次翻译里面。
确定性工具优先；模型只填剩下的部分
机械式重写由每次运行行为都完全一样的脚本来做。模型只用在残渣上 — 清单里打了桩的条目，以及确定性流程拒绝处理的文件。这让移植的大部分保持可复现、可审计，也把模型输出限制在人本来也得手写的那些部分上。
内核里的 C++ 是独立环境的： -fno-exceptions -fno-rtti
内核核心不能依赖宿主环境的 C++ 运行时。不用异常，不用 RTTI，内核入口上不走会在堆上分配的标准库路径。这些约束都写在 docs/specs/KERNEL_CXX_ABI.md 里，好让贡献者不用猜就知道在内核上下文里什么是合法的。
每个模块都要有一条来源记录，才算完成
docs/PROVENANCE.md 记录了每个模块从哪来、在哪个许可证下。正是这一点让下面那段许可说明可以核实，而不只是个愿望 — 你可以一个模块一个模块地查，哪些代码源自 HardenedBSD，哪些是新的 PBSD 工作。

这是给谁用的

一个更难被攻进去的操作系统

大多数入侵利用的是同一类错误：一个程序碰到了它本来就不该碰的内存。ParanoidBSD 用一门让这种错误难得多的语言，把一个受信任的系统重建了一遍，并且只把每个程序真正需要的访问权交给它。

01

国防与政府供应商

采购方开始要求软件用那些能挡掉整类攻击的语言来写。从零重来要花十年。这个做法是把一个已经被验证过的系统搬过去，并且为它改动的每一个文件、以及那次改动是怎么检查的，都留下书面记录。

02

在现场一待就是好几年的设备

工厂控制器、医疗机器、公用事业硬件。缺陷冒出来的时候，你往往没法直接推一个更新。这个做法限制的是入侵者进来之后能走多远，因为没有程序能够到交给它的东西之外。

03

高校与安全研究者

一个真实的操作系统，小到可以从头读到尾，旁边还摆着原件可以对照。既适合教学，也适合在一个真能跑起来的东西上试想法。
