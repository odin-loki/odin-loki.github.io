MathScript · v1.0.0 预发布

一个 C++23 库，从 LU 到 CFD

稠密与稀疏线性代数、特殊函数、统计、ODE/PDE/FEM/CFD、最优化、信号与图像处理、数论、图、几何、拓扑、量子原语、控制、金融、压缩 — 再加一个符号计算 CAS。LU、QR、SVD、特征值求解器和 Cholesky 都写在树内。

  • 树内的 BLAS/LAPACK。 不用 Eigen，不用 OpenBLAS。 linalg 自己拥有 LU、QR、SVD、eig、Cholesky 以及 LAPACK 风格的核心例程，所以部署就是一次编译，而不是一场找依赖的苦役。
  • 一个受限的 C++ 子集。 不用裸指针，不用异常，不用不安全的类型转换 — 编译期强制。生产代码返回 Result<T>，所以错误处理是确定性的，而且在类型里看得见。

      这是给谁用的
      
给程序员的一整套数学工具，就一件东西

      
正经的计算工作通常意味着把十几个各自独立的软件拼在一起，然后指望它们说法一致。这是一个把这些全都覆盖到的库。

    

    

      

        

        01
        
不被允许下载任何东西的团队

        
国防、医疗、航空航天和银行的构建系统常常与互联网隔离。这里的东西全部自带，所以没有要下载的，也没有要报批的。

      

      

        

        02
        
厌倦了把 Python 拴在产品上的团队

        
很多软件用一种语言干正事，用另一种语言算数学，于是有了两套麻烦。这个让数学和产品待在同一种语言里。

    为什么不用异常
    
一个不会朝你扔异常的数值库

    

      数值代码失败的方式都很平常：矩阵奇异、迭代不收敛、特殊函数里的定义域错误。用异常来发这个信号，意味着每个调用方要么把所有东西都包进 try ，要么在栈顶发现失败，却没有任何上下文。MathScript 把失败做成返回类型的一部分。
    

    
// Every production entry point returns Result<T>.
auto lu = linalg::lu_factor(A);
if (!lu) return lu.error();          // singular — handled, not thrown

auto x = lu->solve(b);
if (!x) return x.error();

// No raw pointers, no unsafe casts, no exceptions:
// the restricted subset is enforced at compile time.
